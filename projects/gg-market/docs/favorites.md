# 찜 기능 요구사항

- 문서 상태: 초안
- 마지막 수정일: 2026-10-22

## 1. 사용자 문제

지금 구매하지 않을 상품을 나중에 다시 찾고 싶은 사용자가 상품을 저장하고, 저장 여부를 다시 확인할 수 있어야 한다.

## 2. 관찰과 근거

- 참고 서비스: 네이버쇼핑

- 참고 서비스의 중복 찜 요청, 저장 실패 시 응답, 내부 API와 DB 구조는 확인하지 않았다.

## 3. 사용자 흐름

<!-- 사용자의 행동과 서비스의 응답을 순서대로 적는다. -->

1. 데모 사용자가 상품 1의 찜 여부를 확인한다.
2. 찜하지 않았다면 상품 1을 저장한다.
3. 다시 조회하거나 서버를 재시작한 뒤에도 저장 여부를 확인한다.

## 4. 우리 서비스의 동작 규칙

<!-- 관찰한 사실을 그대로 채택했는지, 재구성을 위해 직접 정한 가정인지 근거에 표시한다. -->

| 번호 | 조건 또는 사용자 행동 | 기대하는 동작 | 근거: 관찰 번호 / 직접 정한 가정 |
| --- | --- | --- | --- |
| R-01 | 데모 사용자가 상품 1의 찜 여부를 조회한다. | 저장 전에는 `saved: false`, 저장 후에는 `saved: true`를 반환한다. | 직접 정한 가정 |
| R-02 | 같은 상품을 여러 번 찜한다. | 이미 저장된 경우에도 성공 처리하고 중복 저장하지 않는다. | 직접 정한 가정 |
| R-03 | 서버를 재시작한다. | 저장한 찜 상태가 유지된다. | 직접 정한 가정 |
| R-04 | DB 저장에 실패한다. | 성공 응답 대신 오류를 반환한다. | 직접 정한 가정 |

## 5. 이번 구현 범위

### 포함

- 고정된 데모 사용자와 상품 1개
- `GET /api/products/1/favorite`로 찜 여부 조회
- `PUT /api/products/1/favorite`로 찜 저장
- PostgreSQL에 찜 상태 저장

### 제외

- React 화면, 찜 해제·목록, 로그인, 네이버 API 연동, 배포

## 6. 완료 기준

<!-- 3~4개를 기본으로, 어떤 상태에서 무엇을 하면 어떤 결과가 나오는지 적는다. -->

- [ ] 저장 전 GET은 `200 {"saved": false}`를 반환한다.
- [ ] PUT 후 GET은 `200 {"saved": true}`를 반환하고, 서버 재시작 후에도 유지된다.
- [ ] 같은 PUT을 두 번 보내면 모두 `204`를 반환하고 DB에는 한 행만 남는다.
- [ ] DB를 중단한 상태에서 PUT을 보내면 성공 대신 오류를 반환한다.
